Проект — набор для Linux VPS, а не серверное приложение Windows. Основной installer использует apt, systemd, `/proc`, nginx, UFW и Linux-бинарники. ### Найденные проблемы

1. **P1 — ложный успех отзыва доступа.** В `scripts/kit.sh:179` и `:219` список записей получается прямо в `for e in $(emails_of ...)`. Если предварительный поиск устройства успешен, но следующий clients/list завершается ошибкой, ошибка command substitution не останавливает цикл: список оказывается пустым. `kit user off` и `kit user del` печатают сообщение об успехе и завершаются с кодом 0 без API-запросов изменения/удаления. Воспроизведено на Windows через Git Bash с исходными функциями clients/emails_of/update_user/cmd_toggle/cmd_del и подменённым недоступным API; живой сервер не изменялся. Тот же update_user используется on/limit. Перед циклом нужно отдельно получать список и проверять код возврата; аналогичную конструкцию awg_ids в awg_attach также следует проверить. **До исправления выпуск не готов.**
2. **P2 — матрица не сообщает провал кодом возврата.** `tests/matrix/matrix-run.sh` печатает ✗, но заканчивается успешным printf и возвращает 0. Воспроизведено с искусственным неработающим клиентом, без сетевых запросов и pkill настоящих процессов. Нужны итоговый ненулевой код при обязательном провале и проверка cd; текущий exit code непригоден для release gate.
3. **P2 — Windows checkout меняет shell-файлы в CRLF.** В этом окружении core.autocrlf=true, атрибуты text/eol не заданы. Текущие shell-файлы имеют LF, но `git cat-file --filters HEAD:scripts/3x-ui.sh` выдаёт 1006 строк CRLF. Следует закрепить `*.sh text eol=lf` и `scripts/repo.conf text eol=lf` в .gitattributes. Преобразование подтверждено, ошибка запуска под Linux здесь не воспроизводилась; Git Bash `-n` принимает такую копию. См. [официальную документацию Git](https://git-scm.com/docs/gitattributes).
4. **P2 — готовая SSH-команда не учитывает нестандартный SSH-порт.** `scripts/3x-ui.sh:364` и `:381` печатают ssh без `-p`, хотя SSH-порт определяется для UFW. При входе на VPS через порт, отличный от 22, туннель по скопированной команде не откроется. Нужно указать реальный порт в итоговом выводе; соединение с реальным SSH-сервером не проверялось.

### Готовность к публикации

На момент проверки публичные GitHub API репозитория McElast/3x-easy-one и оба raw URL install.sh (main/v1.0.0) вернули HTTP 404 без авторизации. Поэтому документированная публичная установка сейчас недоступна; репозиторий может быть отсутствующим либо приватным. Это не ошибка локального bootstrap. Перед распространением также остаётся разобраться с отсутствием LICENSE исходного KIT, уже отмеченным в DEVELOPMENT.md.

Вердикт: **локальные Windows-проверки пройдены в указанном объёме, к релизу текущая версия не готова**. Требуются исправление P1, надёжный результат матрицы, затем сквозная приёмка текущего снимка на чистом Linux VPS: установка, IP-сертификат и его продление, doctor, два устройства, оба AWG, reboot, off/del одного устройства с проверкой прекращения его реальных соединений и сохранения другого. Отдельно проверить Windows GUI/TUN, IPv4/IPv6/DNS, отключение и восстановление сети. Публикация tag/release — после этой приёмки; изменения пока остаются в рабочем каталоге.

## Исправления после аудита — 2026-10-03

Локальные проблемы P1/P2 из аудита выше исправлены:

- `kit.sh` отдельно получает и проверяет список основной/AWG-записей перед on/off/limit/del; ошибка API и пустой список прерывают операцию без сообщения об успехе. Оба awg_attach (CLI и installer) проверяют получение списка AWG.
- Матрица возвращает ненулевой код при провале найденного конфига, пустом наборе и ошибке cd. Останавливает только собственный PID клиента, вместо pkill всех процессов с именами xray/mihomo/sing-box. Пропущенные пары по-прежнему надо сверять с ожидаемой матрицей.
- `.gitattributes` закрепляет LF для `*.sh`, repo.conf и KIT_VERSION; глобальный core.autocrlf не менялся.
- SSH-команда включает `-p`: сначала порт текущего SSH_CONNECTION, иначе единственного listener. Когда выбор неоднозначен/невозможен, installer предупреждает и оставляет заменяемый SSH_PORT. Определение работает и с --no-ufw.

Повторная прицельная проверка: **24 сценария прошли** в Git Bash с исходными функциями, искусственным API и официальным jq 1.8.1 для Windows. Проверены успешные on/off/limit/del основной и twin-записи, сохранение другого устройства и отдельных subId; ошибки повторного clients/list и мутаций; недоступный AWG-list и корректное отсутствие AWG; нестандартный SSH-порт/единственный listener/неизвестный порт/несколько listener; результат матрицы при успехе, провале, пустом и отсутствующем каталоге. jq запускался с --binary в тестовом адаптере, чтобы его Windows stdout соответствовал Linux LF. Живые API, SSH и VPN-соединения этими сценариями не проверялись.

`bash -n` для трёх изменённых shell-файлов прошёл. ShellCheck по ним не добавил предупреждений/ошибок относительно снимка перед исправлением; старые предупреждения остаются. Git checkout filter теперь выдаёт LF, `git diff --check` прошёл. Ad hoc проверки остались в игнорируемом private/, постоянные тесты не добавлены.

Остаётся **приёмка на чистом Linux VPS и реальном Windows-клиенте**, а затем публикация публичного репозитория, стабильного tag и GitHub Release по DEVELOPMENT.md. Исходники должны попасть на VPS одним согласованным комплектом; для локального архива запускается `bash scripts/3x-ui.sh` из корня проекта. Секреты/private/backup не публикуются. Релиз в рамках этого исправления не создавался и код на GitHub не отправлялся; вопрос лицензии исходного KIT остаётся открытым.
