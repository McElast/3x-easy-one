# Проверка работоспособности

Серверная часть KIT рассчитана на Linux с systemd. На Windows можно проверять синтаксис,
сервис подписок с тестовым backend и браузерные генераторы. Для проверки установки и соединений нужен Linux VPS.

## Проверки исходного кода

Из корня репозитория:

```bash
bash -n install.sh scripts/3x-ui.sh scripts/kit.sh scripts/hysteria2.sh
bash -n scripts/repo.conf tests/matrix/mk-inbounds.sh tests/matrix/matrix-run.sh tests/matrix/awg-set.sh
python3 -m py_compile scripts/kit-sub.py scripts/kit-admin.py
node --test tools/test/links.test.js
git diff --check
```

Для JavaScript-файлов в `tools/` и `tests/` используйте `node --check`.
При наличии ShellCheck проверьте shell-скрипты командой `shellcheck -s bash -S warning`.
JSON проверяйте штатным парсером, YAML — PyYAML. Полученный профиль Mihomo проверяется командой
`mihomo -t -f ПУТЬ_К_ПРОФИЛЮ`, конфигурация nginx — командой `nginx -t` с установленным stream module.

Проверьте относительные ссылки и якоря Markdown, адреса загрузки компонентов и правила `.gitignore`.
В репозитории не должно быть пользовательских подписок, ключей, баз данных и резервных копий.
Для тестовых конфигов используйте документационный IP `203.0.113.1` и искусственные ключи.

## Подписки и генераторы

При изменении сервиса подписок проверьте:

- REALITY, XHTTP, Hysteria2, AWG31 и AWG classic в профиле совместимого Mihomo;
- фильтрацию XHTTP/AWG31 для известных старых версий и исключение неподдерживаемого AWG для Stash;
- профиль FlClash, родной формат других клиентов, исключение `vpn://` и `tg://` из base64-подписки;
- явный выбор `format` и `awg31`, запрос HEAD, неверный токен и неизвестный путь;
- обработку ошибочного YAML, недоступного backend и ответа размером более 2 MiB;
- заголовки `Cache-Control: no-store` и `Content-Length`;
- изоляцию Host: пользовательский заголовок не передаётся backend;
- отсутствие токенов, путей подписок и произвольного User-Agent в журнале.

В генераторах Xray и Mihomo проверьте разбор ссылки, создание JSON/YAML и SSH-команд,
переключение вкладок и отсутствие ошибок в консоли браузера.

## Проверка на VPS и устройствах

Перед проверкой подключений отсканируйте QR из `kit user link имя` встроенным сканером клиента.
Проверьте широкий и узкий терминал: в узком должна появиться подсказка о необходимой ширине,
а не QR с переносами. В выводе команды через pipe должна оставаться ссылка без QR.

Локальная проверка QR 2026-10-08: настоящий qrencode 4.1.1, ANSI-вывод CLI и независимый
декодер ZXing-C++. Полученная ссылка совпала с тестовой при размерах ячейки 8×16, 8×17,
9×18 и 10×18 пикселей. Проверены узкое окно, неверная ширина, отсутствие tput, ошибка/отсутствие
qrencode и pipe. Проверка камеры реального Android остаётся обязательной.

1. Установите выбранную версию KIT на чистый тестовый VPS и выполните `kit doctor`.
2. Проверьте выпуск IP-сертификата и `kit-cert-renew.timer`; порт 80/tcp должен оставаться доступным.
3. Создайте двух пользователей для разных устройств и импортируйте их персональные подписки.
4. Проверьте каждый доступный транспорт, включая оба AWG, в Wi-Fi и мобильной сети.
5. Включите TUN или системный VPN. Проверьте внешний IPv4/IPv6, DNS и доступ к локальной сети.
6. Переключите Wi-Fi → LTE → Wi-Fi; проверьте восстановление новых соединений и резервные транспорты.
7. Перезагрузите VPS и устройство. Проверьте запуск служб, обновление подписки и подключение.
8. Выполните `kit user off` и `kit user del` для одного устройства. Его подключения, включая AWG,
   должны перестать работать; второе устройство должно сохранить доступ.
9. Отключите VPN и убедитесь, что обычная сеть и DNS восстановились.
10. Создайте `kit backup` и проверьте восстановление на отдельном VPS по [INSTALL.md](INSTALL.md).

Матрица протоколов и клиентов описана в [tests/matrix/README.md](../tests/matrix/README.md).
Пропущенные пары сверяйте с ожидаемым набором и `cases/index.json`.
Проверка формата не подтверждает доступность транспорта через конкретного оператора.

## Результаты проверок v1.0.0

Проверки выполнены 2–3 октября 2026 года на Linux Mint 22.3 и Windows с Git Bash 5.2.26,
Node.js 22.18.0 и Python 3.14.7. Для YAML использовался PyYAML, для профилей — Mihomo v1.19.30.

| Проверка | Результат |
|---|---|
| Shell | синтаксис 8 shell/config файлов проверен |
| Python | синтаксис `kit-sub.py` и `kit-admin.py` проверен |
| JavaScript | синтаксис 7 файлов проверен; 14 из 14 существующих тестов прошли |
| Подписки | форматы, HTTP-ошибки, лимит ответа, фильтрация транспортов и изоляция Host проверены |
| Mihomo | профиль с REALITY, XHTTP, Hysteria2 и обоими AWG принят командой `-t` |
| nginx | HTTP-конфигурация и SNI stream приняты nginx 1.24.0 со stream module |
| Генераторы | разбор REALITY-ссылки, вывод конфигов и переключение вкладок проверены |
| Ссылки | 50 относительных ссылок на файлы проверены; отсутствующих файлов нет |
| ShellCheck | версия 0.11.0: 26 предупреждений, ошибок на уровне `warning` нет |
| Управление устройствами | 24 сценария CLI, AWG, SSH-портов и запуска матрицы прошли |

Проверки управления устройствами использовали тестовый API. Подтверждены операции `on/off/limit/del`,
сохранение другого устройства и отдельных `subId`, обработка ошибок получения списков и изменения записей.
Матрица проверена при успешном, неуспешном, пустом и отсутствующем наборе.
Проверены нестандартный SSH-порт, единственный listener и неоднозначное определение порта.
Git checkout сохраняет LF в shell/config-файлах.

Сквозная установка, продление сертификата и реальные VPN-соединения не входят в эти результаты.
Для них используйте порядок проверки на VPS и устройствах выше.
