# Установка, повторный запуск и восстановление

[Пользовательская инструкция](../README.md#установка-сервера).

## Чистый VPS

Ubuntu 22.04/24.04 или Debian 12/13, systemd, публичный IPv4, x86_64/arm64. Откройте 80/tcp, 443/tcp+udp, 51821/udp, 51822/udp и фактический SSH-порт также у хостера. Выполните команду stable установки из README от root. Свои DNS-домены не нужны.

Панель ставится официальным installer v3.8.5 в режиме без SSL. Временная копия этого закреплённого installer меняется одной проверенной заменой: localhost bind включается ещё до запуска панели. Привязка затем подтверждается через API. Публичный HTTPS завершается на nginx; через него публикуется только подписка. При ошибке сертификата установка останавливается, сохраняя состояние. Не соглашайтесь на постоянное отключение проверки TLS в основном клиенте.

## Незавершённая установка

Обычный повторный запуск не удаляет БД, пользователей, конфиги и файлы прошлой установки. Завершённая установка направляет к `kit`. Если installer не дошёл до конца:

1. Сохраните `/etc/x-ui`, `/etc/kit`, `/root/cert`, `/root/.acme.sh` вне VPS; если команда `kit` уже есть, запустите `kit backup`.
2. Прочитайте защищённый `/var/log/3x-ui-install.log` лично; не публикуйте его целиком.
3. Исправьте внешнюю причину (порт 80, firewall хостера, связь с GitHub/ACME, место на диске).
4. Выполните installer **той же версии с теми же параметрами** и дополнительным `--resume`. Пример после загрузки stable bootstrap: `KIT_REF=v1.0.0 bash /root/3x-easy-one-install.sh --resume`.
5. `--resume` допускается только для своей установки с сохранёнными install-result.env и KIT_VERSION; сначала автоматически делает backup. Существующие подключения/ключи и пользовательские URL повторно не создаются.
6. После завершения выполните `kit doctor`, проверьте два устройства и старые URL. Если 3X-UI не сохранила install-result.env, автоматическое продолжение невозможно: восстановите snapshot или переустановите **тестовый** VPS через хостера после сохранения нужного состояния.

Не переносите многопортовую установку в single-port автоматически и не используйте `--resume` как обновление чужого/старого KIT. При наличии незавершённого nginx проверьте его до продолжения.

## Backup

`kit backup` использует SQLite online backup и integrity_check, не копирует живую DB вместе со случайно рассогласованным WAL. Архив включает стандартные конфиги панели, настройки KIT/nginx, units, cert-renew, сертификаты и ACME-account, CLI и подписку. Бинарники, логи, caches не нужны для восстановления и не включаются. Стандартная DB: `/etc/x-ui/x-ui.db`; нестандартные DB отдельно.

При активном администрировании не меняйте настройки во время backup: SQLite-копия согласованна, но многокомпонентный архив не является атомарным snapshot всей машины.

## Восстановление — вручную

Автоматический `kit restore` сознательно отсутствует. Смена IP, версии панели, бинарников, путей сертификатов и чужой nginx требуют review. Для надёжного полного rollback используйте также snapshot VPS у хостера.

1. Сохраните текущее состояние: `kit backup` и snapshot VPS. На целевом чистом хосте сохраните хотя бы существующие конфиги и ключи; не заменяйте файлы до проверки архива.
2. Проверьте `tar -tzf ПУТЬ_К_АРХИВУ` и размер архива. Это секретные имена/данные — вывод не публикуйте. Убедитесь, что нет абсолютных путей, `..`, неожиданных файлов. Архивы KIT содержат относительные пути и не включают symlink/hardlink.
3. Распакуйте в отдельный root-каталог 0700, не в корень системы. Прочитайте `BACKUP.json`; сверьте формат, версию и SQLite integrity_check извлечённой DB.
4. Подготовьте **те же** 3X-UI/Xray и пакеты nginx, stream module, Python/PyYAML, curl/jq/openssl/qrencode/UFW. Не запускайте основной installer поверх восстановленной DB. Бинарники 3X-UI восстанавливаются из соответствующего официального релиза; конфиги и пользователи — из проверенного архива.
5. Остановите x-ui, nginx и kit-sub. Проверьте файлы в staging, перенесите только необходимые файлы в штатные пути; снимите старые DB WAL/SHM лишь после остановки панели и backup. Сохраните root:root и права секретов 0600, директорий секретов 0700. Обычные публичные HTML — 0644.
6. Если IP сменился, старый IP-сертификат не подходит: пересмотрите HOST, subURI, внешние адреса протоколов и получите новый сертификат. Обновите URL на устройствах. Восстановление на другом IP не обещает сохранение URL.
7. Проверьте `nginx -t`, `systemctl daemon-reload`, конфиги и права до запуска. Включите необходимые службы и cert-renew.timer. Запустите `kit doctor` и проверьте каждое устройство.
8. При проблемах вернитесь к предварительному snapshot/backup. Не меняйте SSH/firewall в рамках restore.

Этот порядок — инструкция для контролируемого ручного восстановления, не гарантия автоматического disaster recovery.
