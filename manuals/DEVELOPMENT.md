# Разработка и публикация 3x-easy-one

## Архитектура

- `install.sh` загружает архив выбранного тега, commit SHA или `main` и запускает installer из архива.
- `KIT_VERSION` задаёт версию проекта. `scripts/repo.conf` содержит репозиторий, ref и версии компонентов.
  При выпуске обновляйте default ref в bootstrap; команда установки передаёт явный `KIT_REF`.
- `scripts/3x-ui.sh` устанавливает 3X-UI и Xray, создаёт inbounds и клиентов, настраивает сертификаты,
  продление, подписку, nginx и UFW.
- `scripts/kit.sh` управляет пользователями устройств и связанными AWG-записями.
  `scripts/kit-admin.py` выполняет диагностику, SQLite backup и чтение метаданных выпусков.
- `scripts/kit-sub.py` обслуживает подписку через backend 3X-UI. Он задаёт собственный Host,
  ограничивает ответ размером 2 MiB и запрещает кеширование. Для Mihomo строит профиль с `AUTO`/`FALLBACK`;
  для других клиентов сохраняет родной формат. User-Agent и URL не выводятся в журнал.
- REALITY и XHTTP: TCP/443 → nginx stream с разными SNI → 127.0.0.1:10443/10444.
- HTTPS-подписка: TCP/443 → 127.0.0.1:10446 → kit-sub на 10460 → нативный backend на 2097.
  Административная панель доступна только через SSH-туннель.
- Hysteria2 работает через Xray на UDP/443. AWG classic и 3.1 встроены в панель: UDP/51821 и 51822.
- Два AWG используют разные пары ключей и записи клиентов. Команды `off`/`del` применяются ко всем
  связанным записям; трафик суммируется при выводе. Лимиты действуют отдельно на каждую запись.

## Версии и совместимость

3X-UI v3.8.5 и Xray v26.6.27 закреплены в `repo.conf`.
При изменении версий проверяйте совместимость транспортов и клиентов.
acme.sh 3.1.6 используется для IP-сертификата; SHA-256 закреплена в `repo.conf`, auto-upgrade отключён.
Отдельная установка Hysteria использует версию 2.12.3.

Для AWG31 требуется совместимое ядро клиента. Mihomo поддерживает его начиная с v1.19.30.
FlClash v0.8.98 использует core submodule `70f0570405c3c2c47bb113b88db95006d239b346` с параметрами AWG 3.1.
Если User-Agent не содержит подтверждённой версии, подписка выдаётся без AWG31.
Параметр `?format=mihomo&awg31=1` включает его явно после проверки ядра.
XHTTP требует Mihomo v1.19.22 или новее и исключается для явно распознанных старых версий.

TUN в YAML выключен: пользователь включает его в GUI и разрешает создание VPN на устройстве.
Профиль содержит DNS, маршруты и исключения локальной сети.
Генераторы роутера имеют отдельные параметры и не меняют профиль подписки для ПК и телефона.
Их dashboard закреплён на zashboard v3.29.1; удалённые наборы правил обновляются отдельно.

## Проверки

После изменения кода выполните проверки синтаксиса, существующие тесты и проверку конфигов
по [VALIDATION.md](VALIDATION.md). Изменения API, сертификатов и управления устройствами проверяйте
на отдельном тестовом VPS. Пользовательские ключи, подписки и резервные копии не включайте в Git.

## Публикация выпуска

Перед публикацией проверьте diff, историю изменений и результат проверки на тестовом VPS.
Обновите `KIT_VERSION`, закреплённые версии и ref в bootstrap, затем создайте тег:

```bash
git status
git diff --check
git add .gitignore .gitattributes KIT_VERSION install.sh README.md SECURITY.md CHANGELOG.md \
  scripts manuals tools tests index.html
git diff --cached
git commit -m "Release v1.0.0"
git tag -a v1.0.0 -m "Release v1.0.0"
git push -u origin main
git push origin v1.0.0
```

Для следующих выпусков заменяйте номер версии. Создайте GitHub Release из опубликованного тега:
`kit update check` ищет последний стабильный Release. Защитите опубликованные теги от перезаписи.
Сторонние компоненты распространяются по собственным лицензиям.

## Обновление KIT на VPS

`kit update check` читает метаданные выпусков `McElast/3x-easy-one`.
`kit update` создаёт backup и показывает инструкцию ручного обновления. Автоматическая миграция не поддерживается.

1. Выполните `kit backup`, создайте snapshot у хостера и сохраните вывод `kit version`.
   Получите архив нового тега или commit SHA, изучите CHANGELOG и diff.
2. Проверьте совместимость компонентов, `kit.env`, конфигурации подписки, путей и systemd units.
   Изменение схемы БД или протоколов требует отдельного порядка миграции.
3. Проверьте синтаксис всех файлов новой версии. Остановите kit-sub и сохраните старые
   `/usr/local/bin/kit`, `/usr/local/lib/kit`, `/usr/local/lib/kit-sub` и `/etc/kit` для отката.
4. Замените `kit.sh` в `/usr/local/bin/kit`, `kit-admin.py` в `/usr/local/lib/kit/kit-admin.py`,
   `kit-sub.py` в `/usr/local/lib/kit-sub/kit_sub.py`, а `repo.conf` и `KIT_VERSION` — в `/etc/kit`.
5. Сохраните существующие `kit.env` и БД. Установите в `kit.env` значение `KIT_REF` нового тега.
   Права секретных настроек — 0600, исполняемых файлов — 0755, остальных файлов кода — 0644.
6. Запустите kit-sub, выполните `kit version` и `kit doctor`, проверьте подписки и отзыв тестового устройства.
   При сбое восстановите предыдущий комплект и `KIT_REF`.

Не запускайте основной installer как updater. Обновление панели через меню `x-ui` может изменить
закреплённый компонент; перед ним нужны backup и проверка совместимости.
